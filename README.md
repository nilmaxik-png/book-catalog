# Практическое занятие №7 — Карта дорожной обстановки

Мобильное приложение React Native / Expo. Работа находится в ветке `practice-7-traffic` репозитория `nilmaxik-png/book-catalog`.

На карте Нью-Йорка показаны дорожные участки из внешнего API NYC Open Data. Цвет маркера зависит от скорости, нажатие открывает сведения об участке. Кнопка «Обновить данные» повторно обращается к API.

## Установка и запуск

Нужны Git, Node.js LTS и интернет для загрузки карты и дорожных измерений.

Если предыдущие практические уже клонированы, остановите их сервер сочетанием Ctrl+C и выполните:

```sh
cd ~/book-catalog
git fetch origin
git switch practice-7-traffic
npm ci
npm start
```

Для отдельной новой копии:

```sh
git clone --branch practice-7-traffic --single-branch https://github.com/nilmaxik-png/book-catalog.git traffic-map
cd traffic-map
npm ci
npm start
```

После установки зависимостей приложение запускается одной командой `npm start`. Для остановки — Ctrl+C.

### На телефоне

Проект использует Expo SDK 57. На [странице Expo Go](https://expo.dev/go) выберите SDK 57 и установите совместимый клиент для Android. Подключите компьютер и телефон к одной Wi-Fi-сети и отсканируйте QR-код из терминала в Expo Go.

Для iPhone/iPad проверьте [порядок установки совместимого клиента](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/): версия из App Store может не соответствовать SDK проекта. Можно использовать Android или настроенный Android-эмулятор.

В Expo Go карта использует `react-native-maps`: Google Maps на Android и Apple Maps на iOS. Для проверки в Expo Go отдельный ключ Google Maps не требуется. Для самостоятельной сборки Android APK понадобится конфигурация Google Maps по [инструкции Expo](https://docs.expo.dev/versions/v57.0.0/sdk/map-view/).

### В браузере

В работающем терминале Expo нажмите `w` в английской раскладке. Либо вместо `npm start` выполните `npm run web`. Адрес будет показан в терминале; обычно это http://localhost:8081.

Браузерный просмотр использует Leaflet и карту OpenStreetMap. Мобильная версия использует нативную карту React Native. Для защиты мобильной части откройте приложение на телефоне или эмуляторе.

## Откуда берутся данные

- Источник: [NYC DOT Traffic Speeds](https://data.cityofnewyork.us/Transportation/DOT-Traffic-Speeds/i4gi-tjb9).
- Внешний JSON API: `https://data.cityofnewyork.us/resource/i4gi-tjb9.json`.
- API вызывается при открытии приложения и каждом нажатии «Обновить данные».
- Запрашиваются 500 последних записей за текущую календарную дату Нью-Йорка. Из повторов одного участка выбирается последнее измерение.
- Записи с ошибкой датчика, отсутствующей скоростью, нулевым временем проезда и некорректными координатами исключаются. Ошибочное последнее измерение не заменяется старым успешным.
- Количество показанных участков зависит от ответа источника; это выборка датчиков, а не все дороги города.
- Время получения ответа и время измерения показаны отдельно. `data_as_of` приходит без часового пояса и отображается как метка источника, без пересчёта на часовой пояс телефона.

API доступен для этих запросов без ключа. При сетевой ошибке приложение показывает сообщение и сохраняет ранее полученные маркеры с их исходным временем. Если первоначальная загрузка не удалась, карта остаётся доступна, а данные можно запросить повторно. Время ожидания запроса — 20 секунд.

### Цвет маркеров

Цвет — учебная оценка по скорости, вычисленная в приложении. Это не официальный индекс пробок NYC DOT. Исходная скорость в милях в час переводится в км/ч умножением на `1.609344`.

| Цвет | Состояние | Скорость |
| --- | --- | --- |
| Зелёный | Свободно | От 40 км/ч |
| Жёлтый | Средняя загрузка | От 20 до 40 км/ч, не включая 40 |
| Красный | Пробка | Менее 20 км/ч |

При нажатии показаны название дороги, район, состояние, скорость, время проезда и метка времени датчика. После обновления карточка выбранной дороги использует новое измерение. Если участка больше нет в ответе, карточка закрывается.

Повторное обновление может вернуть те же показатели: частотой измерений управляет источник данных.

## Структура проекта

- `App.js` — карта, легенда, кнопка обновления и выбранный участок.
- `hooks/useTraffic.js` — загрузка, состояние запроса, отмена и обработка ошибок.
- `services/trafficApi.js` — HTTPS-запрос к внешнему API и тайм-аут.
- `domain/traffic.js` — проверка записей, координат, скорости и выбор цвета.
- `components/TrafficMap.native.js` — нативная карта и маркеры.
- `components/TrafficMap.web.js`, `components/map.web.css` — браузерная карта Leaflet.
- `components/RoadDetails.js` — информация по выбранному маркеру.
- `styles.js` — стили React Native.
- `tests/` — автоматические проверки расчётов, ответов API и сетевых ошибок.

## Проверка и защита

1. Клонируйте нужную ветку, установите зависимости и запустите приложение.
2. Дождитесь появления маркеров и количества участков.
3. Покажите легенду трёх цветов.
4. Нажмите на маркер: появится информация о дороге.
5. Нажмите «Обновить данные»: на время запроса кнопка будет недоступна, затем обновится время получения ответа.
6. Покажите время измерения, которое приходит из API.
7. При необходимости отключите интернет и обновите данные: появится сообщение об ошибке, предыдущие измерения останутся с прежним временем.
8. Покажите [историю отдельных коммитов](https://github.com/nilmaxik-png/book-catalog/commits/practice-7-traffic/).

```sh
git log --oneline --graph
npm test
```

Проверка экспорта:

```sh
npm run export:web
npm run export:android
```

Экспорт Android создаёт JavaScript/Hermes-бандл, а не установочный APK. Каждый экспорт записывает результат в `dist`.

При подготовке прошли 11 автоматических проверок и экспорт для Android и веба. В браузере проверены ответ настоящего API, загрузка карты, три цвета маркеров, карточка участка, обновление, ошибка сети и ширина экрана 390 пикселей. Физический телефон или эмулятор в среде подготовки не запускался.

## Коротко о коде для защиты

- `useState` хранит измерения, выбранный участок и состояния загрузки/ошибки.
- `useEffect` запускает первый запрос, а при закрытии приложения отменяет незавершённый.
- `fetch` получает JSON по HTTPS; `response.json()` превращает ответ в объекты JavaScript.
- `Map` оставляет последнее измерение для каждого `link_id`.
- Координаты из `link_points` превращаются в `latitude` / `longitude`.
- Цвет вычисляется из скорости, а `Marker.onPress` выбирает идентификатор участка.
- Карточка каждый раз ищет выбранный идентификатор в актуальном массиве измерений.
- Кнопка обновления вызывает тот же обработчик, что и первоначальная загрузка. Одновременные повторные запросы блокируются.
- Суффиксы `.native.js` и `.web.js` позволяют использовать подходящую карту на каждой платформе.
