# Практическое занятие №6 — Мобильный трекер привычек

Мобильное приложение на React Native и Expo. Ветка проекта: `practice-6-habits`.

## Установка и запуск на телефоне

Нужны Git, Node.js 24 LTS и Expo Go на телефоне.

```sh
git clone --branch practice-6-habits --single-branch https://github.com/nilmaxik-png/book-catalog.git habit-tracker
cd habit-tracker
npm ci
npm start
```

После запуска появится QR-код. Компьютер и телефон должны находиться в одной Wi-Fi-сети.

- Android: откройте Expo Go и отсканируйте QR-код.
- iPhone: отсканируйте QR-код камерой и откройте проект в Expo Go. Если приложение запросит вход, используйте один Expo-аккаунт в Expo Go и в CLI (`npx expo login`).
- Остановка сервера: Ctrl+C.

Используется Expo SDK 57: на момент подготовки работы документация рекомендует эту версию для Expo Go на физических устройствах в переходный период SDK 58.

Если доступ по Wi-Fi не работает, можно попробовать `npm start -- --tunnel`. Expo может предложить установить компонент туннеля.

## Запуск без телефона

```sh
npm run web
```

Это браузерный режим того же React Native приложения для предварительного просмотра. Адрес показан в терминале. Мобильную демонстрацию можно провести через Expo Go или настроенный эмулятор Android.

Для уже настроенного эмулятора Android:

```sh
npm run android
```

Для iOS Simulator на macOS:

```sh
npm run ios
```

## Возможности

1. Экран «Привычки»: список и количество выполненных привычек.
2. Экран «Добавление привычки»: поле названия, кнопки добавления и отмены.
3. Название обязательно, до 80 символов; пробелы по краям удаляются.
4. У каждой привычки есть кнопка отметки выполнения и её отмены.
5. Список и отметки сохраняются через AsyncStorage.
6. После повторного открытия приложения сохранённые данные восстанавливаются.
7. При ошибке чтения или записи отображаются сообщение и кнопка повторной попытки.

Отметка выполнения сохраняется до ручной отмены; ежедневный сброс не используется.

Перед закрытием дождитесь сообщения «Данные сохранены на устройстве». Пока идёт начальная загрузка, редактирование недоступно, чтобы пустой массив не перезаписал сохранённый список.

## Структура

- `index.js` — регистрация корневого компонента Expo.
- `App.js` — Stack Navigation с двумя экранами и передача данных.
- `screens/HabitsScreen.js` — список, отметки и счётчик.
- `screens/AddHabitScreen.js` — форма добавления.
- `hooks/useHabits.js` — состояние, загрузка и последовательное сохранение.
- `storage/habitsStorage.js` — чтение и запись AsyncStorage, проверка формата.
- `styles.js` — стили React Native через `StyleSheet`.
- `app.json` — конфигурация Expo.
- `package.json`, `package-lock.json` — зависимости и команды.

В нативном приложении нет HTML и CSS: используются компоненты `View`, `Text`, `Button`, `TextInput`, а оформление вынесено в `styles.js`.

## Проверка на защите

1. Клонируйте ветку, выполните `npm ci`, затем `npm start`.
2. Откройте проект в Expo Go или эмуляторе.
3. Нажмите «Добавить привычку»: откроется второй экран.
4. Попробуйте добавить пустое название: появится ошибка.
5. Добавьте «Читать 20 минут» и «Делать зарядку».
6. Отметьте одну привычку: изменятся подпись, оформление и счётчик.
7. Дождитесь завершения сохранения, перезапустите приложение: список и отметка восстановятся.
8. Отмените выполнение: изменение тоже сохранится.
9. Покажите историю коммитов на GitHub.

## Дополнительные проверки сборки

```sh
npm run export:android
npm run export:web
```

Эти команды экспортируют код и ресурсы в `dist`. Android-экспорт является JS/Hermes-бандлом для приложения, а не установочным APK.

При подготовке проверены экспорт Android и веб-версии, восстановление состояния, очередь записи, обработка ошибок, форма и обработчики экранов. Автоматические проверки логики использовали тестовое хранилище и компоненты; физическое устройство или эмулятор в среде подготовки не запускались.

## Ответы по коду

- `View` — контейнер, `Text` — текст, `TextInput` — ввод, `Button` — кнопка.
- `useState` хранит массив привычек и состояние формы.
- `useEffect` загружает данные и запускает сохранение при изменении массива.
- `useRef` хранит очередь записи и счётчик идентификаторов между рендерами.
- Stack Navigation открывает экран добавления поверх списка; `goBack()` возвращает к списку.
- AsyncStorage хранит строки: `JSON.stringify` сериализует объект, `JSON.parse` восстанавливает его.
- При отметке создаются новый массив и новый объект выбранной привычки через `map`.
- Записи выполняются последовательно, поэтому медленная старая запись не перезапишет более новое состояние.
